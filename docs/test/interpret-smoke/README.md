## 浏览器端联调方法

无头 Chromium 以 `--use-fake-device-for-media-stream --use-file-for-fake-audio-capture=<wav>` 把 E4 数据集的合成语音当作麦克风输入，
脚本按真实用户操作完成"选择模式 → 设置语言/引擎/高级选项 → 开始 → 结束"，同时监听页面 WebSocket 事件。会议室场景用两个独立浏览器进程、两个不同账号。

## 联调中发现并已修复的问题

| # | 现象 | 原因 | 修复 |
|---|---|---|---|
| 1 | 同传收听连接后立即报 A0410 | Spring 对非对话模式传 `converseRouting: null`，Python 只接受 auto/ptt | Python 把 null 视为 auto（`StreamConfig`），补测试 |
| 2 | 结束时最后一句以空译文落库 | Spring 发 end 后立即关闭 Python 连接，收尾期间的事件被丢弃 | 结束改为优雅收尾：停止转发新音频，等待各发言流处理完积压句子（≤8 s）再关闭落库，补测试 |
| 3 | 会议室结束后统计变成"1 人 / 仅中文 / 无延迟" | 前端在 WS end 后又调 REST 结束接口，房间已移出内存，误走"残留会话"兜底写入 | 收尾期间房间保留在内存中，并发结束请求共享同一次收尾；收尾中拒绝新成员加入，补测试 |
| 4 | 延迟逐句递增（4.6 → 5.3 → 6.1 s） | 指标终点取"音频按序发出"时刻，包含等待上一句音频发完的排队 | 改为"首段译音就绪"时刻（播放本就在客户端按序进行） |
| 5 | 开口第一句被截掉 | 前端先开麦克风，WS 建立前的音频帧被丢弃 | 连接前预录缓冲（≤3 s），连上后补发 |
| 6 | 级联同传只能用默认的推理模型，延迟 5–7 s | 准备页没有翻译模型选项 | 高级设置增加「翻译模型（级联）」，选 qwen-turbo 后约 3.5 s |
| 7 | 译图边缘露出原文笔画 | 视觉模型 bbox 比实际字形略小，覆盖只外扩 1 px | 覆盖区按框高等比外扩（水平 12%、垂直 18%） |
| 8 | 百炼单人会议室没有原文 | 目标集合为空时不建上游会话 | 借占位目标建会话，只转发原文与指标 |
| 9 | 同传中刷新页面后状态全部丢失，再次开始提示"已有进行中的同传会话" | 前端运行时状态只在内存中；服务端会话保留 60 s 等待重连，前端却无从得知 | 新增 `GET /api/interpret/sessions/active`；准备页顶部恢复卡片（继续同传 / 结束并重新开始），继续时以创建者身份重连并回放已落库转写、计时接续；A0214 返回进行中会话并触发卡片抖动提示；进行中刷新或关闭页面先弹离开确认（截图 `refresh-*.png`） |
| 10 | 大量转写段没有译文 | 转写段合并只等 5 s，级联链路的译文定稿要等首段译音合成出来，常常超时，迟到的译文被丢弃 | 等待放宽到 15 s，超时写入后迟到的译文与指标回填到原行 |
| 11 | 刷新瞬间正在翻译的句子丢失 | 浏览器断开时 Spring 立即硬关闭发言流 | 断线改为收尾：发送 end，等 Python 处理完已切出的句子（≤8 s）再关闭，期间不再上行音频 |

## 已知限制

- 级联链路的端到端延迟约 3.3–4.4 s（偶发 6 s），主要由翻译首字（约 1.5 s）与 edge-tts 首包（约 1.4–1.9 s）构成；百炼 S2S 边说边译，句末后 0.5 s 内即有译音。
- 无头浏览器没有扬声器，播报由播放队列的保护超时结束；真实浏览器中播报会触发半双工门控（未开耳机模式时）。
- OpenAI / Gemini / 豆包三个 S2S 引擎只完成了协议实现与模拟服务测试，未配置真实密钥联调。
