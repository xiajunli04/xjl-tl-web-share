## Context

现状链路（⑦ / ⑧.3 / ⑧.4 之后）：

```
浏览器 AudioWorklet（16 kHz PCM16，40 ms/帧，回声消除 / 降噪 / 自动增益）
  → Spring /ws/interpret（同源代理）→ Python /internal/interpret/stream
  → 级联：Silero VAD（静音 500 ms / 极速 300 ms 即判句末）→ SenseVoice 整段识别 → 翻译或对话回复 → 分段 TTS
  → 事件经 Spring 改写 utteranceId 为 "<participantId>:<n>" 后广播 → 前端 reduceLive 按 utteranceId 归并 → 各视图渲染
```

浏览器只负责采集与上行，断句完全在服务端。问题集中在以下几处。

**1. 断句只看静音时长**
- 自然的思考停顿（0.5–1.5 s）会把一句话切开。半句被单独翻译和播报，AI 对话在停顿时就开始回复。
- 实时语音模型的 `server_vad` 也配成 500 ms，低于百炼缺省值 800 ms。

**2. SenseVoice 的句末标点不可信**
- 探针做法：从语音数据集取 20 句中英文整句音频，在中段低能量处切开，两半分别识别。
- 结果：所有半句都补上了句末标点，例如：
  - "请问去。"
  - "大家好，今天我们讨论新版本的。"
  - "Let's move on to the."
  - "Most of the growth came."
- 尾段还会出现 "."、"Pop." 之类的噪声文本。
- 因此"有没有句末标点"不能用来判断是否说完。另外，拼接两段识别文本会得到"新版本的。发布计划。"，合并续说时必须对拼接后的音频重新识别。

**3. 半双工门控**
- 单设备模式未开耳机时，播报开始就暂停上行，用户正在说的后半句丢失。
- AI 对话中，用户停顿 → AI 抢答 → 播报关麦，用户无法接着说。

**4. 前端空白光标框**
- 级联在首个 partial 时分配 utteranceId。最终识别为空时直接 `return`，那条只有 partial 的语句永远不会定稿，光标一直闪。
- 会议室 `Message` 不过滤"没有原文也没有译文"的语句。只有 metrics 或译文的语句（S2S 引擎的噪声句）会渲染成空白气泡加光标。
- 收听舞台在原文为空时单独显示光标。

**5. 实时语音对话的顺序错乱**
- 用户转写（whisper / gummy 异步）常晚于 AI 回复的首个事件。
- 前端按到达顺序追加，用户气泡出现在 AI 回复下方。

**6. 抖动**
- 每个 `translation.delta` / `transcript.partial` 都会触发整列重渲染，并重启一次 `scrollTo({behavior:"smooth"})`。
- 整句重识别的 partial 可能前后大幅变化，整行闪烁。

约束：
- 单人开发，CPU 推理（SenseVoice 2 线程）。
- 不更换 ASR。
- 协议只做增量扩展，旧前端不会因此出错。
- 所有改动要有可复现的评测数据支撑。

## Goals / Non-Goals

**Goals:**
- 句中停顿（≤ 1.2 s 同传 / ≤ 2 s 对话）不再切碎句子。完整句的断句延迟不高于现状。
- 纯语气词与噪声不成句，不翻译、不回复、不播报。界面上不残留空白气泡或孤立光标。
- AI 对话不抢话：AI 回复开始播放之前，用户继续说可以让位；咳嗽不会打断 AI。
- 半双工模式下，播报尽量不在用户说话时开始。
- 实时字幕流式更新平滑：稳定前缀、淡显尾部、跟随滚动不抢控制、顺序正确。
- 用 E6 停顿鲁棒性评测量化改动前后的效果，并据此决定 Smart Turn 是否默认开启。

**Non-Goals:** 见 proposal「非目标」：
- 不换流式 ASR；
- 不用 LLM 判断句末；
- 不做句末前投机生成；
- 不改 S2S 上游断句；
- 不迁移 OpenAI GA 接口；
- 浏览器端不加载神经网络 VAD。

## Decisions

### D1 两段式断句状态机（Endpointer）

**决策**：把断句逻辑从 `CascadeEngine` 中抽出，放到 `app/speech/endpointing.py` 的 `Endpointer`。CascadeEngine 只把它的判定结果映射为事件。

状态与转移：

```
IDLE ──VAD 开始说话──▶ SPEAKING ──VAD 静音达到候选阈值（产出语音段）──▶ JUDGING
JUDGING：对"已挂起音频 + 本段"重新识别 → 判定（D2）
  ├─ 空文本 且无挂起内容             ──▶ 丢弃（D4）──▶ IDLE
  ├─ 纯语气词 且无挂起内容           ──▶ HOLDING（可能正在想词，如"嗯……我想问"；超时仍无内容则丢弃）
  ├─ 空文本 / 纯语气词 且有挂起内容 ──▶ 本段只并入音频，不改判定；重新计时 ──▶ HOLDING
  ├─ 说完 / 强制条件（见下）       ──▶ COMMIT（transcript.final）──▶ IDLE
  └─ 未说完                         ──▶ HOLDING（发 partial{hold:true}）
HOLDING ──VAD 再次开始说话──▶ SPEAKING（同一 utteranceId，partial 基于合并音频）
HOLDING ──续说等待超时（音频时钟；墙钟兜底）──▶ COMMIT（复用最后一次识别结果，不再识别）
任意状态 ──flush（按键松开 / 静音 / 结束 / 门控）──▶ 立即 COMMIT（或丢弃）
```

强制 COMMIT 条件：
- flush；
- 本段是 VAD 达到 `max_speech_s` 被强制切出的长段（时长 ≥ max − 0.2 s），说明是连续长句，保持现状逐段出句；
- 合并后语音总时长 ≥ `merge_max_s`。

计时：
- 续说等待按**音频时钟**计（HOLDING 后收到的采样数），离线评测因此可以确定性地快速回放。
- 另设墙钟兜底（等待时长 + 300 ms），覆盖门控或断流时没有音频帧的情况。
- 兜底通过向处理队列投递 `_HoldExpire(token)` 实现，仍由单个处理协程消费，不引入并发。

参数（服务端配置可调）：

| 参数 | 同传·均衡 | 同传·极速 | 对话·均衡 | 对话·极速 |
|---|---|---|---|---|
| 候选静音（VAD min_silence） | 500 ms | 300 ms | 500 ms | 300 ms |
| 未说完时的续说等待 | 700 ms | 400 ms | 1500 ms | 1000 ms |
| 合并上限（语音时长） | 12 s | 8 s | 20 s | 20 s |

- LISTEN、CONVERSE、ROOM 使用"同传"档；CHAT 使用"对话"档。
- 未说完时的最长静音：同传 1.2 s / 0.7 s，对话 2.0 s / 1.3 s。这与业界区间一致：LiveKit 0.5–3 s，AssemblyAI Balanced 0.4–1.28 s，Pipecat 3 s 兜底。
- 续说等待设为 0 时，行为退化为现状（回滚开关）。

**备选方案**：
- 直接把 VAD 静音调到 1.2 s：所有句子都多等 0.7 s，同传延迟明显变差。
- 只在前端把相邻气泡拼起来：翻译与播报仍是碎句，治标不治本。

**理由**：
- 只有"判为未说完"的句子才付出额外等待，完整句延迟不变。
- 判定与等待逻辑独立成类后，离线评测和单测可以绕过 WS 与 LLM 直接驱动。

### D2 "是否说完"的判定：Smart Turn v3 主判 + 文本强规则

**决策**：判定器 `TurnJudge` 按顺序执行：
1. **文本规则**：取识别文本，去掉末尾标点与空白，按最后一个词分强 / 弱两档。以**强延续词**结尾的判为未说完：
   - 中文虚词与连接词：的 / 地 / 得 / 和 / 跟 / 与 / 把 / 被 / 给 / 对 / 从 / 在 / 向 / 往 / 是 / 要 / 想 / 会 / 能 / 就 / 也 / 还 / 而且 / 但是 / 可是 / 所以 / 因为 / 如果 / 然后 / 那个 / 这个 / 就是 / 比如 / 还有；
   - 英文：冠词、介词、连词、物主代词、系动词与情态动词；
   - 语气词（复用 `lang_notes.FILLERS` 并补全 ja / ko）。

   表格放在 `endpointing.py` 的 `CONTINUATION_WORDS`，中日韩按后缀匹配，拉丁语按末词匹配。
2. **声学模型**（可用时）：Pipecat Smart Turn v3 int8 ONNX。
   - 输入为合并音频的最后 8 s，按官方 `inference.py` 的约定：WhisperFeatureExtractor 参数为 80 mel、chunk_length=8、max_length 填充与截断、波形归一化。
   - 输出为 sigmoid 概率，≥ 阈值（缺省 0.5）判为说完。
3. **弱延续词**（如中文"的、是、要、在"，英文 to / for / in / is）单看文本容易误判：有模型时，要求完成概率 ≥ `confident`
   （缺省 0.99）才算说完；没有模型时直接判为未说完。实测合成中文的半句在逗号处也有降调，模型给分普遍在 0.95–0.98，
   单靠缺省阈值区分不开"…新版本的"这类半句。
4. **模型不可用**（文件缺失、onnxruntime 加载失败或推理异常）：除上述规则命中外，一律判为说完，即退化为现状并加上文本规则。

**实现要点**：
- 特征提取用 numpy 移植 Whisper log-mel（STFT n_fft=400、hop=160、Slaney mel 滤波器组、log10、动态范围截断、(x+4)/4），不引入 transformers。
- 一致性测试：用 transformers 一次性生成参考特征（固定随机音频），存为 `tests/fixtures/whisper_mel_ref.npy`，单测比较的误差 < 1e-4。transformers 只在生成参考数据时临时使用，不进依赖。
- 推理通过 `asyncio.to_thread` 进行，使用独立的 `InferenceSession`（1 线程），与 SenseVoice 互不阻塞。

**备选方案**：
- 只用文本规则：探针表明句末标点不可用，只剩末词规则，召回有限（"Most of the growth came." 无法识别）。
- LiveKit 0.5B 文本模型：约 400 MB，CPU 上 50–160 ms，中文依赖转写质量。
- 以 LLM 判定：每句多一次网络往返。

**理由**：
- Smart Turn 基于音频，能捕捉"语调未落下"等文本没有的信息。
- 体积 8 MB，CPU 推理约 10–60 ms，BSD-2 许可，支持中文。官方报告中文准确率 88.6%。
- 文本强规则能兜住模型最容易错的"以虚词结尾"的情况。

**启用策略**：
- 配置 `endpoint_smart_turn` 取 `auto | on | off`。
- 预先约定的达标线：碎句率下降 ≥ 50%，且完整句的判定延迟 p50 增加 ≤ 150 ms；达标则缺省 `auto`，否则缺省 `off`。
- **E6 结果（合成语音）：未达标，缺省 `off`**。同传·均衡档阈值 0.5 时碎句率 84.4% → 71.3%、延迟 +139 ms；
  提高阈值（0.9–0.98）碎句继续减少，但完整句延迟增加 300 ms 以上，0.95 起还会把两句误合并。
  文本规则单独使用即可零代价减少碎句（AI 对话档短语中间切点的碎句率 80.8% → 56.7%）。
  模型与代码保留，`ENDPOINT_SMART_TURN=auto` 即可开启；合成语音的停顿语调与真人不同，真人数据可能改变结论。

### D3 续说合并：重识别拼接音频

**决策**：
- 挂起期间保留已挂起语音段的原始采样，与新语音段直接拼接（中间插入 120 ms 静音），整体重新识别。
- partial 同样基于"挂起音频 + 当前进行中段"，所以续说时气泡文字是在增长，而不是被重置。
- `startedMs` 取首段开始，`endedMs` 取末段结束。utteranceId 从首次分配起保持不变。

**理由**：
- 探针显示，分段识别再拼接文本会出现两个句号和错词，如"灰度发布。覆盖5%的用户。"。
- 整段识别还能恢复跨段的词，例如 "Warterly" → "quarterly"。
- SenseVoice 非自回归，12 s 音频在 2 线程下识别耗时可接受。合并上限把最坏情况限制在 20 s 内。

**备选方案**：把文本拼接后交给 LLM 修复。这会增加一次调用和延迟，且错词无法从文本中恢复。

### D4 语气词与噪声：撤回而不是保留

**决策**：
- 定稿时，如果识别文本去掉标点和语气词后为空，就丢弃该句：
  - 不发 `transcript.final`，不翻译，不回复；
  - 如果此前已为该句发过 partial（已分配 utteranceId），发 `transcript.discard{utteranceId}`。
- 有效文本的最小长度：中日韩 1 个字，拉丁语 1 个字母数长度 ≥ 2 的词。单字回答如"好""对""是""不"、"OK""no" 仍然成句。
- AI 对话中丢弃的句子不触发回复；如果正处于让位等待（D6），触发恢复。
- Spring 收到 `transcript.discard`：
  - 照常广播；
  - 从 `RecentUtterances` 移除该句；
  - 调用 `SegmentWriter.discard(sessionId, utteranceId)`：移除待合并段；已写出的行则删除。
  - 不新增错误码。

**理由**：
- 主流语音助手对"VAD 触发但转写为空"的轮次直接丢弃。
- 由服务端发撤回事件比前端靠超时猜测更可靠。前端另有兜底规则（D9），覆盖不发撤回事件的 S2S 引擎。

### D5 协议扩展（接口契约）

下行事件（Python → Spring → 浏览器，Spring 改写 utteranceId 并补 speaker）：

| 事件 / 字段 | 说明 | 兼容性 |
|---|---|---|
| `transcript.discard{utteranceId, role?}` | 撤回一条尚未定稿的语句：用户噪声 / 语气词，或 AI 让位撤回的回复。客户端移除该句 | 旧前端忽略未知事件（`parseServerEvent` 返回 null），残留的气泡与现状相同 |
| `transcript.partial.hold?: boolean` | true 表示服务端判为未说完、正在等待续说 | 可选字段 |
| `metrics.holdMs?: number` | 本句在续说等待中累计停留的时长；e2eMs 口径不变（最后一段语音结束 → 首段译音），因此包含这段等待 | 可选字段；Spring 落库时保留 |

上行控制帧：

| 控制帧 | 说明 |
|---|---|
| `{type:"interrupt", yield?: true}` | yield=true 表示让位：撤回最近一条尚未开始播放的 AI 回复（D6）。缺省为原打断语义。Spring 原样转发 |

**单句事件顺序约定（修改「一句话的事件顺序」）**：
- 若干 `transcript.partial`，其中可能有带 `hold:true` 的；
- 然后**二选一**：
  - 一个 `transcript.final`，后续与现状一致；
  - 一个 `transcript.discard`，此后该 utteranceId 不再有任何事件。

**接口不变的部分**：
- 无新增 HTTP 接口与错误码；
- Python 内部 WS 路径、鉴权与 config 帧结构不变。端点参数由 Python 根据 `mode` 与 `latencyMode` 自行选择。

`docs/contracts/speech-image-api.md` §1.8 / §2.6 同步更新。

### D6 AI 对话：回复让位与插话门槛

**让位流程**（级联 CHAT）：

```
用户句 U1 定稿 → AI 回复 R1 开始生成（可能已产出文本 / 音频，客户端尚未开播或被择机推迟，见 D7）
用户继续说：客户端收到本人新的 transcript.partial，且有效（去语气词后 ≥ 2 字或 1 词）
  且 R1 尚未开始播放 → 客户端丢弃 R1 的排队音频，本地隐藏 R1，发 interrupt{yield:true}
服务端：取消 R1 的生成、字幕与合成，发 transcript.discard{R1, role:assistant}
  R1 不写入对话记忆与记录（如已写入记忆则移除；已定稿的转写段由 Spring discard 撤销）
  记下"待恢复轮次" = U1；启动恢复计时（yield_resume_s = 3 s）
接着：
  ├─ 新用户句 U2 定稿 → 正常回复。记忆中 U1、U2 相邻，chat_prompts.normalize 合并为同一轮 → AI 回应完整意思
  └─ 续说被丢弃（噪声）或计时到期仍无定稿 → 重新为 U1 生成回复
```

- 已经开始播放的回复不让位，走原有的打断逻辑：耳机模式自动插话，半双工模式点「打断」。
- 实时语音模型（realtime-chat）的回合由上游决定，不做让位；只受益于 D8 的断句参数。

**插话门槛**：
- `shouldAutoInterrupt` 增加条件：用户 partial 文本有效（与让位相同的判定 `isMeaningfulSpeech`）。
- 咳嗽、"嗯"不再打断 AI。
- 对应业界的 `min_interruption_words` / `min_interruption_duration`。

**备选方案**：服务端在用户恢复说话（VAD）时直接撤回回复。但服务端不知道回复是否已在客户端开播，可能撤回一条用户已经听到一半的回复，所以由客户端判定。

**理由**：
- 等价于 Deepgram Flux 的 EagerEndOfTurn / TurnResumed 模式：定稿即生成，开播前可撤回。
- 不增加首字延迟，同时消除抢话后"上下文里有一条用户没听到的回复"的问题。

### D7 半双工择机开播

**决策**：
- `AudioQueue` 新增开播门 `setStartGate(canStart: () => boolean, maxDeferMs)`。
- `pump()` 在开始**新的一句**前检查开播门。不满足时每 100 ms 复查，自该句首包到达起超过 `maxDeferMs`（4 s）后强制开播。
- 已开始的句子不暂停。重播（用户主动操作）不受影响。

`canStart` 在以下两种情况下为 false：
- 本机用户正在说话：电平 ≥ 说话阈值且持续 ≥ 120 ms，并保留 600 ms 挂起时间；
- 本机有未定稿的语句：最近 3 s 内收到过本人 partial，且该句尚未 final 或 discard，包括 hold 中的句子。

**生效范围**：
- LISTEN / CONVERSE 未开耳机（半双工）时生效；
- CHAT 总是生效（不论是否开耳机），即 AI 不在用户说话时开口；
- ROOM 不生效（多人广播，各自开播）。

播报开始导致门控关闭时，如果本机仍有挂起的语句（hold），客户端发 `flush`，让服务端立即定稿，不再等待续说。

**理由**：
- 半双工本身不变（播报时不收音，规避回声）。改动只在"何时开始播报"：在说话间隙开播，这也是交替传译的自然节奏。
- 4 s 上限保证连续讲话（如讲座）时播报不会无限积压。真正的解决办法仍是耳机模式，界面会给出提示。

### D8 实时语音模型断句参数

- 百炼 Omni：
  - 缺省 `server_vad`，`silence_duration_ms = realtime_chat_silence_ms`（缺省 800 ms，范围 200–6000）；
  - 模型名以 `qwen3.5-omni` 开头时使用 `semantic_vad`（官方仅列出 Qwen3.5-Omni-Realtime 系列支持）。
- OpenAI 兼容：`turn_detection = {type:"semantic_vad", eagerness: realtime_chat_openai_eagerness}`，缺省 `low`，面向语言学习者停顿较长的情况。
- 管理员可以在模型配置 `extra.turnDetection` 中用 `server` / `semantic` 覆盖自动选择。
- OpenAI 适配器仍标"实验"。据第三方报道 beta 头已下线，本变更不做 GA 迁移，在 Risks 中注明。

### D9 前端归并与渲染

**归并（`reducer.ts`，纯函数并有单测）**：
- `transcript.discard` → 移除该句（AnimatePresence 退出动画）。
- **按序插入**：新语句的 id 形如 `<stream>:<n>` 时，插到同一 stream 中第一个序号更大的语句之前（只在末尾 50 条内查找）；无法解析则追加。实时对话中迟到的用户转写因此排在它触发的 AI 回复之前。
- **过期收尾**（兜底，覆盖不发 discard 的引擎）：同一 stream 中更大序号的用户语句定稿时，更早的未定稿用户语句处理如下：
  - 没有任何译文的直接移除；
  - 有译文的标记为定稿，不再显示光标。
- 语句新增 `hold` 与 `updatedAt` 字段。
- 派生函数 `visibleText(u, lang)` / `isDisplayable(u, view)`：没有可显示文字的语句不渲染。

**批量归并**：
- `InterpretRuntime.onEvent` 中，非 audio 事件先入队，每个动画帧调用一次 `store.applyMany(events)`；页面隐藏时改用 50 ms 定时器。
- 读取最新状态前先 `flushPending()`，例如 `interrupt()`、让位判定。
- 消息行组件 `React.memo`：reducer 对未变化的语句保持对象引用不变，只有变化的行重渲染。

**流式文本（`StreamingText`）**：
- 计算与上一次文本的最长公共前缀，拉丁语回退到词边界。前缀正常显示；尾部降低不透明度，并按尾部起点为 key 做 120 ms 淡入。
- 只有"当前进行中"的语句显示光标：未定稿、非 hold、且为该视图最后一条进行中语句。hold 时显示三点呼吸动画。
- reduced-motion 下不做淡入，只保留颜色区分。

**跟随滚动（`useStickToBottom`）**：
- 距底部 ≤ 96 px 视为"在底部"。内容变化（ResizeObserver）时，在 rAF 中直接设置 scrollTop，不做平滑滚动；只在新语句出现时平滑滚动。
- 用户上翻后不再自动滚动，并显示"新消息 · n"胶囊，点击后平滑回到底部。

**正在听指示（`ListeningIndicator`）**：
- 本机已开口（电平说话态或有未显示文字的进行中语句）但还没有可显示的气泡时，消息流底部显示带声波条的"正在听…"胶囊。
- 会议室中其他成员 `speaking` 时显示"某某正在说话…"。
- 气泡出现时，胶囊以 layout 动画让位给气泡。

**连续消息分组**：
- 会议室：同一发言人 60 s 内的连续消息，后续条不重复显示头像与名字，间距缩小，气泡圆角衔接。
- AI 对话：用户侧连续气泡（让位产生的 U1、U2）同样分组。

### D10 E6 停顿鲁棒性评测

**数据**：由 `evaluation/data/speech` 的 40 句派生，脚本生成到 `data/speech_pause/`，不手工录音。
- **V0 原句**：完整句延迟基线。
- **V1 句中停顿**：在 35%–65% 区间内 RMS 最低的 40 ms 窗口处切开**原始整句音频**，插入 600 / 900 / 1200 ms 静音。保留句中语调，不使用分开合成的两个半句，因为那会带有句末降调。
- **V2 停顿 + 语气词**：在切点插入 edge-tts 合成的语气词（zh "嗯…"、en "um…"、ja "えーと"、ko "음"），两侧各留 300 ms 静音。
- **V3 两句间隔**：同场景相邻两句之间留 700 ms 静音，期望切成两句，用于测误合并。

**两级评测**：
- **离线断句评测**（主）：直接驱动 `Endpointer`（真实 VAD / SenseVoice / Smart Turn），按音频时钟快速回放，不调用 LLM。统计：
  - 碎句率（V1 / V2 中一句原句产出多于 1 个定稿的比例）；
  - 误合并率（V3）；
  - 语气词成句数；
  - 判定延迟：最后一段语音结束 → 定稿，按 p50 / p90；
  - 定稿文本对参考原文的 CER / WER。
- **端到端抽检**：沿用 E4 推流方式，取 V0 / V1 各 10 句，统计 e2eMs、holdMs 与整句 chrF。

**对照组**：
- `baseline`：续说等待为 0，即旧行为；
- `rules`：只用文本强规则；
- `smart`：文本规则 + Smart Turn；
- 以上各组在同传·均衡、同传·极速、对话·均衡三档下运行。

**输出**：
- `results/multimodal/e6_runs.jsonl`、`e6_summary.csv`、`e6_latency.png`；
- 报告 `docs/test/endpointing/report.md`。
- E6 运行过程与结论写入报告，不写入论文实验章节，是否写入由用户决定。

## UI/UX

**信息架构**（不改变布局，只改变消息流的"生命周期"）：

| 视图 | 消息流的分层 |
|---|---|
| 收听 | 原文行（StreamingText + hold 呼吸点；无文字时显示声波"正在听"）→ 舞台大字幕（只显示有目标语文本的句子）→ 可折叠历史字幕 |
| 对话 | 两半区各自的气泡列；本侧未出字时，半区底部显示"正在听"；本句 hold 时气泡尾部显示呼吸点 |
| 会议室 | 成员条（说话脉冲环）→ 统一消息流（分组气泡、"某某正在说话…"指示、"新消息"胶囊）→ 控制条 |
| AI 对话 | 数字人舞台（状态说明增加"等你说完…"：hold 时）→ 对话流（用户侧分组、让位时 AI 气泡淡出、"正在听"胶囊） |

**关键交互流程**：
1. **说话带停顿**（同传）：
   - 开口 → 底部"正在听"；
   - 出字 → 气泡出现，光标跟随，尾部淡显；
   - 停顿且判为未说完 → 光标变为呼吸点，状态胶囊显示"识别"；
   - 继续说 → 同一气泡内文字继续增长；
   - 说完 → 定稿，译文流入。
2. **咳嗽或只说"嗯"**：
   - 可能短暂出现"正在听"，然后消失；
   - 不出现气泡，不翻译、不播报，AI 不回应。
3. **AI 抢答后用户接着说**：
   - AI 气泡（思考点或已出的文字）淡出并收起；
   - 用户第二段气泡与第一段分组显示；
   - AI 对两段话一并回应。
4. **半双工用户还在说**：
   - 译文已到但不开播，状态胶囊保持"识别 / 翻译"；
   - 用户停下后开播，或等待 4 s 后开播。
5. **浏览历史时有新消息**：不抢滚动；"新消息 · 2"胶囊从底部弹出，点击后平滑回到底部。

**动效清单**（motion 库，统一使用 `DURATION` / `EASE_OUT` 令牌，尊重 reduced-motion）：

| 动效 | 规格 | reduced-motion |
|---|---|---|
| 气泡进入 | opacity 0→1，y 10→0，page 时长 | 仅淡入 |
| 撤回 / 让位退出 | opacity→0，height→0，scale 0.98，fast 时长 | 直接移除 |
| partial 尾部 | 新尾部 opacity 0.35→0.6，120 ms | 无动画，仅浅色 |
| hold 呼吸点 | 三点依次 opacity 0.3↔1，1.2 s 循环 | 静态省略号 |
| 正在听胶囊 | 声波条高度随电平变化（复用 LevelOrb 的 motion value，不触发重渲染），进出 popLayout | 静态图标 |
| 新消息胶囊 | 从底部 y 8→0 弹出，spring | 仅淡入 |
| 分组衔接 | 相邻气泡圆角与间距过渡，layout="position" 仅在插入或移除时生效 | 无 |

## Risks / Trade-offs

- **[Smart Turn 漏判（说完了判成没说完）] → 该句多等一个续说等待时长。**
  - 阈值与等待时长由 E6 标定；
  - 等待有硬上限；
  - 可一键关闭（`endpoint_smart_turn=off`）。
- **[E6 用合成语音（edge-tts），停顿语调与真人有差距] → 结论可能偏乐观。**
  - V1 切原句而不是拼接半句；
  - 报告中注明局限；
  - 建议用户录 10 句带自然犹豫的真人语音做抽检（见 Open Questions）。
- **[重识别合并音频，长句定稿耗时增加]**
  - 合并上限为同传 12 s / 对话 20 s；
  - 保留"识别让路"（D4.1）；
  - E6 统计判定延迟 p90。
- **[择机开播推迟译文播放（讲座类连续讲话）]**
  - 最多推迟 4 s；
  - 收听模式检测到连续推迟时提示"建议开启耳机模式"（每次会话一次）。
- **[让位误触发（背景人声被识别为有效文字）] → AI 回复被撤回后会恢复，最多晚 3 s。**
  - 有效语音门槛；
  - 只在回复尚未开播时让位。
- **[按序插入依赖 Spring 的 id 格式 `<pid>:<n>`] → 无法解析时退回按到达顺序追加。**
- **[协议新增事件，旧前端不识别]** → 旧前端忽略它，表现与现状相同（残留气泡），不会出错。新前端兼容不发 discard 的引擎（过期收尾兜底）。
- **[OpenAI beta 接口据报已下线] → 该适配器可能已不可用，本变更无法联调验证。**
  - 保持"实验"标注；
  - GA 迁移另起变更。
- **[中文延续词规则误伤]** 例如以"的"结尾的完整口语句"挺好的"，会被判为未说完。
  - 设例外表，收录常见的完整说法：是的、好的、对的、真的、挺好的、可以的、没问题的等，以单测固定；
  - 误伤最坏也只多等一个续说等待。

## Migration Plan

1. **部署顺序**：Python → Spring → web。
   - 协议是增量扩展，三端任意先后上线都不会出错；
   - 只有三端都上线后才具备完整体验。
2. **模型**：`uv run python -m app.speech.download` 缺省同时下载 Smart Turn v3 int8（约 8 MB，HuggingFace，支持 `SPEECH_HF_MIRROR` 镜像如 `https://hf-mirror.com`）。下载失败只告警，不影响其他模型。
3. **回滚**：
   - 续说等待配置为 0 且 `endpoint_smart_turn=off` → 断句行为与现状一致；
   - 实时语音模型参数可单独回退；
   - 前端改动独立于后端开关，无需回滚。
4. **数据**：无 DDL 变更。`SegmentWriter.discard` 只删除本会话中同一 utteranceId 的转写行。

## Open Questions

1. **同传·均衡档的候选静音是否从 500 ms 降到 300 ms**：有 Smart Turn 兜底时可以缩短完整句延迟。由 E6 在两种取值下对比后决定，缺省保持 500 ms。
2. **Smart Turn 是否缺省开启**：以 D2 的达标线判定。
3. **真人语音抽检**：需要用户用自己的声音录 10 句带自然停顿的话（中英各 5 句），放入 `evaluation/data/speech_pause/human/`（不入库），作为 E6 的补充验证。没有录音时报告只给合成数据结论。
