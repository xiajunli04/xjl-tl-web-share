## Why

平台目前的上下文能力集中在篇章一侧（全文摘要、专名表、前块上下文）。总体设计 §4.4 规划的"会话为辅"一线和 §7 的"翻译记忆"至今仍是空白：短文本每次翻译都相互独立，`TranslationContext` 中的 `session_ctx`、`tm_examples` 两个字段只是预留。这带来两个问题：

- **连续对话**（客服回复、多轮沟通）中的指代、省略和称谓无法借助前文理解，用户想微调译文也只能整段重来。
- **用户确认过的历史译法**（后编辑的段落、收藏的译文）无法沉淀复用，同一用户反复遇到相似句子时，平台不会"记得"他上次的选择。

题目要求的"上下文翻译"和总体设计中的"人机协同（歧义追问）"也需要这部分能力来补全。这是路线图的最后一项。

## What Changes

### 翻译会话（会话上下文 B）

- 工作台新增**会话模式**：
  - 用户可以新建或切换会话，同一会话中的多轮翻译共享上下文。
  - 会话记忆沿用 ContextMemory 抽象：最近 N 轮原文与译文作为短期窗口，更早的轮次压缩为摘要，另有人名、称谓、专名等实体表。
  - 翻译时作为 `session_ctx` 注入提示词。
- **迭代修订**：对会话中的任一轮译文，用自然语言提出修改要求（"更口语一些""把 refund 译为退款"），Agent 结合原文、当前译文和会话上下文给出新版本，各版本可以回看和切换。
- **歧义主动追问**：
  - 会话中的标准路径翻译里，plan 节点在判定领域的同一次 LLM 调用中检查歧义，例如多义词、性别或称谓不明、指代不清。
  - 发现歧义时，通过 LangGraph `interrupt` 暂停，向用户提出带选项的问题。
  - 用户回答后从断点继续翻译，回答写入上下文。
- **SSE 协议扩展**：新增 `clarify` 事件，一次事件流可以以 `clarify` 结束，表示等待用户回答；新增恢复接口，以事件流方式继续执行。

### 翻译记忆（pgvector）

- 新增**用户级翻译记忆库**，存放用户确认过的原文与译文对，三个来源：
  - 工作台「存入记忆」。
  - 文档段落后编辑保存时自动写入。
  - 文档任务完成后一键写入全部译文。
- **混合检索**：
  - 本地多语种 embedding 模型（384 维）做语义检索。
  - pg_trgm 三元组做字面模糊检索。
  - 两路结果合并后，按 CAT 工具惯用的模糊匹配度排序，并给出匹配度百分比。
- **检索结果用作 few-shot 参考**：
  - 短文本标准路径的 retrieve 节点检索后作为 `tm_examples` 写入提示词。
  - 文档分块翻译按块检索，新增实验选项 `translationMemory`，默认开启。
  - 命中情况通过事件与轨迹展示。
- **翻译记忆管理页**：列表、检索、查看来源、删除。

### 评测

新增三组小规模实验，数据写入实验报告：
- 翻译记忆的留一法实验：用其他 4 篇的历史译文作为记忆，翻译第 5 篇。
- 会话上下文对多轮对话翻译的影响：自建多轮客服对话测试集，比较带与不带会话上下文。
- 歧义检测的精确率与召回率：自建有歧义与无歧义的句子集。

## Capabilities

### New Capabilities

- `translation-session`：翻译会话的创建、列表、删除，会话记忆（短期窗口、摘要、实体表）的构建与更新，迭代修订，歧义追问与恢复。
- `translation-memory`：翻译记忆的写入（三种来源）、本地 embedding、混合检索与匹配度、管理接口与管理页。

### Modified Capabilities

- `text-translation-agent`：
  - 翻译参数新增可选的 `sessionId`。
  - Agent 编排新增修订路径和追问中断。
  - 上下文包中的 `session_ctx`、`tm_examples` 开始填充。
  - 工作台新增会话侧栏、修订输入、追问卡片和「记忆」标签页。
- `translation-streaming`：事件协议新增 `clarify` 与 `memory` 事件，事件流可以以 `clarify` 结束；新增恢复接口。
- `translation-history`：翻译记录关联会话与修订来源，历史详情显示所属会话与版本。
- `document-agent`：分块翻译按块检索翻译记忆，作为参考写入提示词；新增实验选项 `translationMemory`。
- `document-task`：段落后编辑保存时写入翻译记忆，新增"写入全部译文"接口；创建参数新增 `translationMemory` 选项。
- `document-workspace`：段落详情显示翻译记忆命中情况，任务菜单新增「写入翻译记忆」。
- `ablation-experiments`：新增翻译记忆留一法、会话上下文、歧义检测三组实验。

## Impact

- **springboot-backend**：
  - Flyway V5：新建 `biz.translation_session`；`translation_record` 增加 `session_id` 和 `revision_of`；新建 `ai.translation_memory`（向量列、HNSW 与三元组索引，授权 tl_ai 读写）。
  - 新增会话模块（会话 CRUD、修订与追问回答的流式接口），以及翻译记忆模块（对外接口，转发给 Python 内部接口）。
  - 文档段落编辑写入翻译记忆。
- **python-backend**：
  - 新增 `app/memory/`：embedding 提供方、翻译记忆仓储与混合检索、会话记忆的压缩与实体抽取。
  - 短文本图：新增 revise 路径和追问中断；检查点使用 AsyncPostgresSaver，并为状态类型配置序列化白名单。
  - 新增内部接口：`/internal/translate/resume`、`/internal/tm/*`。
  - 文档分块检索翻译记忆。
  - 新增依赖 `fastembed`（ONNX 推理，模型约 220 MB，首次启动时下载并缓存，支持 HF 镜像）。
- **web**：工作台会话侧栏与对话线程、修订输入与版本切换、追问卡片、Agent 面板「记忆」标签页、翻译记忆管理页、文档工作区的记忆命中显示与写入入口。
- **evaluation**：
  - 新增数据集：`data/session/dialogues.jsonl`（多轮对话）、`data/session/ambiguity.jsonl`（歧义句）。
  - 新增执行器与指标，实验报告新增第 10 节。
- **兼容性**：不带 `sessionId` 的翻译请求行为与现在完全一致；新增事件和字段对旧客户端透明。

## 非目标

- 不做会话上下文 A（双人跨语言对话模拟），它在总体设计中是"可选"项。
- 不做翻译记忆 100% 匹配时跳过 LLM 直接复用。命中结果只作为 few-shot 参考，直接复用留作后续优化。
- 不做 TMX/CSV 导入导出，以及团队共享或公共翻译记忆，记忆库只按用户隔离。
- 不在快速路径和非会话请求中做歧义追问，以免打断单次翻译的体验。
- 不引入外部 embedding API。中转站不提供 embedding 模型，统一使用本地模型；提供方抽象保留扩展点。
- 不重跑 D 系列与 I 系列实验。新实验只针对本变更的新增能力。

  - ②：短文本 Agent、翻译记录与 SSE。
