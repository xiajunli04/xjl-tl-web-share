# 会话上下文与歧义检测测试集（自建）

用于 add-session-context-and-memory 的 E2、E3 实验（实验报告第 10 节）。两份数据都由本人编写，规模小，结论只作参考。

## dialogues.jsonl（E2：会话上下文）

- 12 段英文客服、服务类对话，每段 5 轮，共 60 轮，目标语言中文。
- 每轮的 `phenomena` 标注**需要前文才能正确翻译**的片段：
  - `span`：原文片段
  - `type`：现象类型
  - `expected`：正确译法的判定说明（交给评审模型使用）
- 第 1 轮一般只用来建立语境，不做标注。

构造原则：

1. 覆盖中文翻译中真实存在的上下文依赖，共 49 项：
   - 以代词所指 `pronoun`（14）、省略与替代 `ellipsis`（14，如 the one / theirs）、性别 `gender`（8，she/he → 她/他）为主。
   - 另有专名前后一致 `entity`（5）、前文已经消歧的多义词 `polysemy`（4，如 charge → 充电/扣费）、称谓与敬语一致 `register`（3）、亲属称谓 `kinship`（1）。
2. 单独看本轮时有可能译错，看了前文就能确定正确译法。
3. 句子都是常见客服用语，避免生僻词，使差异主要来自上下文。

## ambiguity.jsonl（E3：歧义检测）

- 20 句有歧义的句子（`ambiguous=true`），标注歧义片段 `span` 和可能的读法 `readings`；另有 20 句无歧义的常见客服句。
- 有歧义的句子分两类：
  - 中文必须区分而英文不区分的亲属称谓，如 cousin、uncle、nephew。
  - 在没有上下文时，不同读法会导致不同中文译法的多义词，如 bank、bill、bat。
- 每句都在独立的新会话中提交（没有前文），因此歧义无法通过上下文消解。
